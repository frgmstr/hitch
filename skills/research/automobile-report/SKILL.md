# Automobile Report Skill

Rebuilds a vehicle listing report from live scrapes driven through the local browser
instance, then verifies every figure against the scraped pages.  This is a **generic**
fork of an internal Bronco-only pipeline — it works for any automobile you configure via
`TARGET_MAKE`, `TARGET_MODEL`, and `TARGET_YEARS` in `.env`.

It does NOT pull an inventory API directly (that is `visor-vin-api`); instead it consumes
listing/VIN detail data that the companion rubric skill or a manual scrape has already
cached.  Builder is stdlib Python; scraping runs in a browser session via CDP on port 9222.

## When to Use

- "Redo / rebuild the vehicle report" — re-ground all figures against fresh scrapes.
- A saved rows file looks corrupt, or quoted prices need re-verification.
- Yesterday's report cites VINs that may have been sold — re-scrape before quoting any of them.
- **Don't use for:** vehicles outside your configured `TARGET_MAKE`/`TARGET_MODEL` set.

## Prerequisites

1. A Visor.vin API key in `.env` as `VISOR_API_KEY` (required).  Get one at [visor.vin](https://visor.vin).
2. Personalization variables in `.env`:
   - `TARGET_MAKE` — e.g. `TOYOTA`, `FORD`, `HONDA`
   - `TARGET_MODEL` — exact model name as used by Visor.vin / dealers (e.g. `4RUNNER`)
   - `TARGET_YEARS` — inclusive range, e.g. `2023-2025`
3. Local browser at the path below, automation instance on port 9222 with a **dedicated**
   user-data-dir (the everyday profile refuses remote debugging):

   | Platform | Default path | Override via env |
   |---|---|---|
   | Windows | `C:/Program Files/Google/Chrome/Application/chrome.exe` | `BROWSER_PATH` |
   | macOS   | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` | `BROWSER_PATH` |
   | Linux   | `google-chrome` (on PATH) | `BROWSER_PATH` |

4. Archive directory: defaults to `./archives` under the profile root, or whatever you set in
   `$HERMES_ARCHIVE_DIR`.  All input/output files live there.

## Input / Output Files

All paths are resolved relative to `ARCH = $HERMES_ARCHIVE_DIR` (default `./archives`):

| File | Role | How to provide |
|---|---|---|
| `visor_details_cpo_active.json` | listing_id → detail dict pulled from Visor.vin | Run the rubric pipeline or a manual scrape; see `automobile-value-rubric`. |
| `report_rows.json` | shortlisted rows (`{"picks": [...]}`) used for verification | Generated by your selection step. |
| `vehicle_report.html` | rendered report (output) | Written here, then open in a browser tab via `browser_exec`. |

## Verification Step

After building, render `{ARCH}/vehicle_report.html` in a browser tab and require:
- zero broken images (`document.images` all have `naturalWidth > 0`)
- every row's price + VIN present in the HTML.
